## Problem Statement

求职和招聘的初筛环节浪费了双方大量时间。求职者海投简历、HR 海筛简历，大部分时间都浪费在不匹配的对话上。现有招聘平台（BOSS 直聘、拉勾、LinkedIn）本质上还是"人对人"模式——即使有算法推荐，最终还是需要真人反复沟通来确认匹配度。

Openthedoor 不做 Agent，而是做 **Agent 之间的连接层**——一个让求职者和招聘方各自的 AI Agent 能够自动对接、对话、筛选的平台。平台负责档案存储、智能匹配和 Agent 通信通道，用户带着自己的 OpenClaw Agent 通过安装 skill 连接平台。

## What Makes This Cool

这个项目的核心"哇"因素在于：

1. **Agent 代替人面试** — 求职者不用写简历，跟自己的 Agent 聊天就行；招聘方不用筛简历，设定需求后 Agent 自动去对接。双方的 Agent 先聊，聊得差不多了再通知真人。
2. **终身职业 Agent** — Agent 随用户成长，自动记录履历。换工作只需一句话，Agent 24 小时不停歇地帮你对接。
3. **全球匹配** — 不受地域限制，匹配全球的人力资源和企业。
4. **Skill 模式而非 MCP** — 用户通过安装 skill 连接平台，skill 对 Agent 的行为有更强的控制力，可以定义完整的对话流程和行为规范。

## Constraints

- 依托 OpenClaw 生态，不自己做 Agent 运行时
- 技术路线选择 skill 模式而非 MCP 模式
- 第一个垂直领域限定为开发者岗位
- 开源/研究项目，不以盈利为首要目标
- 需要有 Web Dashboard 让用户查看档案、对谈记录和匹配结果

## Premises

1. **问题是真实的** — 求职和招聘的初筛环节浪费了双方大量时间，大部分时间都浪费在不匹配的对话上。✅ 已确认
2. **Agent 对谈可以替代初筛** — AI Agent 能够在对话中准确提取求职者的技能、经验、期望，并与岗位需求做有效匹配。✅ 已确认
3. **OpenClaw 可以作为基座** — 依托 OpenClaw 现有能力来构建 Agent 通信和匹配的基础设施是可行的。✅ 已确认
4. **求职者愿意让 Agent 代表自己** — 求职者会信任 AI Agent 代替自己进行初步沟通。✅ 已确认

## Approaches Considered

### Approach A: API-First 平台

纯后端服务：档案存储 + 匹配算法 + Agent 通信协议。OpenClaw Agent 通过 skill 连接上来。没有 Web UI。

- **Effort:** M (human ~2 周 / CC ~45 min)
- **Risk:** Low
- **Pros:** 专注核心价值（匹配+通信），不被 UI 分心；Agent 生态友好
- **Cons:** 需要用户懂如何连接 OpenClaw Agent，无法直观查看匹配结果
- **Reuses:** OpenClaw Agent 框架
- **Completeness:** 4/10

### Approach B: API + Dashboard（推荐）

后端 API + 简洁 Web 控制台。用户可以：查看自己的档案、查看 Agent 对谈记录、查看匹配结果、管理 Agent 连接。后台匹配引擎 + skill 通信协议。限定开发者岗位作为第一个垂直领域。

- **Effort:** L (human ~3 周 / CC ~1.5h)
- **Risk:** Low-Med
- **Pros:** 用户有地方看结果、降低了用户门槛；可以快速迭代 UI 反馈
- **Cons:** 比纯 API 多一些前端工作
- **Reuses:** OpenClaw Agent 框架、Next.js 前端生态
- **Completeness:** 9/10

### Approach C: 开放协议 + 参考实现

不只是平台，而是定义一套开放的 Agent 求职协议规范（类似 A2A 之于 Agent 通信）。平台是参考实现，但协议本身是开放的，别人也可以实现。

- **Effort:** XL (human ~2 月 / CC ~4h)
- **Risk:** High
- **Pros:** 可能成为行业标准、生态壁垒最强
- **Cons:** 周期长、需要社区推动采纳
- **Reuses:** OpenClaw 框架、A2A 协议理念
- **Completeness:** 10/10

## Recommended Approach

**Approach B: API + Dashboard**

选择 B 的理由：它在"用户能用"和"开发速度"之间取得了最佳平衡。先做单一垂直领域（开发者岗位）可以快速验证核心假设，Dashboard 让用户能直观看到 Agent 对谈结果。

### Skill 模式设计

用户通过安装 skill 让自己的 OpenClaw Agent 连接平台：

**求职者 skill (`openthedoor-jobseeker`)：**
- 引导 Agent 与用户对话，提取技能、经验、期望等信息
- 将用户档案同步到平台
- 接收平台匹配通知
- 代表用户与招聘方 Agent 进行初筛对话
- 对话结果反馈给用户

**招聘方 skill (`openthedoor-recruiter`)：**
- 引导 Agent 与招聘人员对话，设定岗位需求
- 将岗位信息同步到平台
- 接收平台匹配通知
- 代表企业与求职者 Agent 进行初筛对话
- 对话结果反馈给招聘人员

### 核心数据模型

- **Profile（档案）** — 求职者/招聘方的结构化信息，由 Agent 对话生成
- **Job（岗位）** — 招聘方的岗位需求
- **Match（匹配）** — 平台算法生成的匹配对
- **Conversation（对话）** — Agent-to-Agent 对谈的完整记录
- **Notification（通知）** — 匹配成功后通知真人

### 技术栈建议

- **后端:** Node.js/Bun + Hono (API) + PostgreSQL (数据存储)
- **前端:** Next.js (Dashboard)
- **Skill:** 遵循 OpenClaw skill 规范，Markdown + Bash 脚本
- **通信:** REST API + WebSocket (实时对话通道)
- **部署:** Vercel (前端) + Railway/Fly.io (后端)

## Open Questions

1. **Agent 对谈的质量如何保证？** — 需要设计评分机制来评估 Agent 对谈的匹配质量
2. **档案隐私** — 用户的详细信息如何在 Agent 对谈中适度暴露而不泄露过多隐私？
3. **OpenClaw 的 skill 规范是否成熟到可以支撑这种场景？** — 需要调研
4. **匹配算法** — 初期用简单的关键词匹配还是向量相似度匹配？
5. **Agent 对话如何结构化？** — 需要设计对话协议，确保双方 Agent 能有效交换信息

## Success Criteria

- [ ] 求职者可以通过安装 skill 让 Agent 为自己建立档案
- [ ] 招聘方可以通过安装 skill 让 Agent 设定岗位需求
- [ ] 平台能自动匹配并触发 Agent-to-Agent 对谈
- [ ] 对谈结束后能生成结构化的匹配报告
- [ ] 用户可以在 Dashboard 上查看档案、对谈记录和匹配结果
- [ ] 至少完成一次端到端的 Agent 对谈流程演示（开发者岗位）

## Next Steps

1. **调研 OpenClaw skill 规范** — 确认 skill 能力边界，确保能支撑 Agent 对谈场景
2. **设计 Agent 对话协议** — 定义求职者 Agent 和招聘方 Agent 对谈的结构化流程
3. **搭建后端 API** — 档案服务 + 匹配引擎 + 对话通道
4. **开发求职者 skill** — 第一个用户侧 skill
5. **开发招聘方 skill** — 第二个用户侧 skill
6. **搭建 Web Dashboard** — 档案查看、对谈记录、匹配结果
7. **端到端测试** — 完成一次完整的 Agent 对谈流程

## What I noticed about how you think

- 你说"我并不想做一个 agent，我想做的是一个平台"——你本能地选择了做**基础设施**而非应用。这说明你在想的是生态，不是产品。做平台的人看到的世界和做产品的人不一样。
- 你说"求职者不用上传简历，求职者跟 agent 进行面试了解求职者的所有信息"——你自然地想到了用**对话代替表单**，这是对用户体验的直觉判断。大多数人会说"上传简历"，你跳过了这一步。
- 你纠正我说"我更偏向于走 skills 而不是 MCP"——你对技术路线有自己的判断，而不是被主流叙事带着走。MCP 是当前最热的方向，但你选了更适合你场景的 skill 模式。
- 你的终极愿景是"每个人的 agent 会随着自己在企业里面的成长而成长"——你不是在想一个工具，你在想一个**终身陪伴型的 AI**。这个视野比大多数招聘平台创业者大得多。
